# Troubleshooting

## Check a frame before delivering it

The agent validates every frame with the same parser the phone uses, so one request answers "will this draw?":

- **`render_preview`** (MCP tool) — use it first, every time: it draws a frame the way the phone does and returns the picture plus the warnings; with `nextFrame` it also tells glide from cross-fade and draws the in-between frames. No device and no approval needed.

- **You have a shell on the Mac** (Claude Code, a terminal): post the frame yourself through the agent's private socket — no token is needed, so none ends up in the transcript or on a command line. With the phone connected any UUID will do for a syntax check (a real `cellId` also shows the frame on the button); without a phone the agent answers `503` before it reports warnings — use `render_preview` then.
  ```bash
  zsh widget.zsh --frame 42 | curl -q -s -m 5 --unix-socket "$HOME/Library/Application Support/Desmaptic/LocalAPI/agent.sock" \
    -H 'Content-Type: application/json' -d @- http://localhost/api/update-button
  ```
  Never `cat` the token file (`~/.desmaptic-mcp-token`) and never put the token on a command line: it would land in the conversation, and any app on the Mac can read command lines. The token is for the scripts the agent starts — they have it in `$DESMAPTIC_TOKEN`. If the socket is missing, the agent is not running (or is paused because another macOS user is active).
- **You only have the MCP tools**: `run_probe` runs a one-off command on the Mac (off by default — the user turns on *Allow AI to Run Commands* in Security in the agent window and approves each call on the phone). Otherwise deliver the button and read the delivery result: saved faces are parsed by the tool, and its message lists warnings.

Answers: `200 {"status":"ok"}` — accepted. `200` with `"warnings": […]` — accepted, but each listed thing was ignored or approximated: fix until the list is empty. `200` with `"compatibility": […]` — the frame is fine, but an older phone app treats the named part differently without telling anyone (an empty `<text>` is dropped → cross-fade): it matters only when the user's app is old. `400 svg.source rejected: <line, reason>` — not drawn at all. `400 Unknown field(s)` — a misspelled key (inside `svg` they are `source`, `landscapeSource`, `duration`, `easing`, `fit`, `remove`). `503` — no phone connected.

`200` means *accepted*, not *on screen*: frames for a page that is not showing wait on the agent and appear when it opens.

## Symptoms

| What the user sees | Cause | Fix |
|---|---|---|
| the face blinks / cross-fades on every update | the structure changes between frames: an element appears or disappears, a point count varies, `fill` or `stroke` switches between `none` and a color, `rx` between 0 and non-zero, a parked twin without the live element's stroke or gradient | read `crossFade` in the agent's answer to the post (or `lastFrame.crossFade` in `get_startup_script_status`): it names the first element that differs. One template; hide with `opacity="0"`; pad series to a fixed length (`svg-craft.md`) |
| values jump instead of moving | `duration` is 0 | a `duration` of 0.3 s or more (a 0.1 s glide shows as a few steps on older devices) |
| continuous motion turns into steps after a while, or a glide changes its pace | `duration` / `easing` were sent once: a reset, `svg.remove` or a terminated tap script dropped them, and the phone went back to 0.4 s easeInOut | send `duration` and `easing` with every frame |
| a chart wobbles vertically like liquid | the series is re-sent shifted by one sample | the rest + slide scroll recipe |
| the motion stands still for a moment about once a second, though the average frame rate looks fine | the loop holds a frame back for its own limit (level requests counted per second, a timer) — the frame rate is higher than the limit allows | frames no faster than the limit, a margin on a windowed limit (16 a second for 15 frames), a refused frame drawn from the last data; judge by the time between your posts, not the average |
| motion stutters, pauses between steps | `duration` shorter than the real loop period on continuous motion | `easing: "linear"`, `duration` = 1.25 × the measured period (1.2–1.35×); a sparkline's rest + slide keeps × 1.0–1.1 with a period of 1 s or more (`svg-craft.md`) |
| motion that never rests stops for a split second now and then, mostly on Wi-Fi | the glide is barely longer than the period (× 1.0–1.1): the phone gets frames in bursts, up to ~0.15 s late, and a late frame finds the glide over | `duration` = 1.25 × the period (1.2–1.35×): a glide still running is taken over at the same speed; the motion then trails its frames by a quarter step. `view_live_button` flags linear frames whose glide outlasts their gap by less than ~0.15 s and by less than 1.2× |
| something flies backwards across the picture now and then | a looping value was wrapped (360→0, right edge→left edge) and the wrap was glided | let the number grow, or use the invisible jump (`scenes.md` §3) |
| a faint copy of something just hidden slides across the picture, or a mover flies in from far away | it was moved in the same frame that hid it: a fade is not over when the next frame comes, so the move is glided while it still shows | hide it in place in one frame, move it in a later one still at `opacity="0"` (a `<text>` by `opacity`, never `fill-opacity`), show it after that (`scenes.md` §3); a parked mover comes and goes the same way |
| something that keeps moving while it fades out (a spinner, a drifting cloud) vanishes at once instead of fading to the end | a frame moved it while it was hidden: any move of a hidden element cuts what is left of its fade | hold its numbers still for the frames after the one that hides it, until the fade is over (`scenes.md` §3) |
| the halves of a mover part at a button border, or one half leads and slides back into the other | the tiles glide on different clocks: another `duration` or `easing`, a tile posted a tick later or every few ticks while a mover can reach it; or an entering mover's hidden frame drawn at its frame's place, ahead of where the phone shows it | every tile that shows motion gets a frame at every tick with one `duration` and `easing`, posted back to back over one connection; draw a fast mover's entering frame where the phone shows it (`scenes.md` §4) |
| a whole tile cross-fades when a mover comes into it or leaves | the parked twin is not a copy of the live element: a stroke or gradient missing, another tag, path letters or point count, cap, join, dash count, `fill-rule` or clip | make the twin the live element with other numbers (`scenes.md` §2); `crossFade` in the answer names the element |
| a scene warms the phone or gets `"dropped": true` with few movers | big `path` / `polygon` / `polyline` / `line` shapes — a ridge or a seabed across the whole world in every window — or paths whose points change in every frame | cut long shapes into one piece per window, draw large areas as `rect`s, move shapes whole by `transform` (`svg-craft.md` → Keeping the phone smooth); falling `postsLastMinute` in `get_startup_script_status` is the same sign. Keep backing off while answers carry `dropped` (`live-widgets.md`), but a slower tick by design does not help |
| the button is blank | the frame was rejected (the 400 says why; the phone lists it among its errors), or the drawing is there but transparent / outside the viewBox | check the response; check the viewBox against your coordinates |
| a gradient stroke disappears when the line is flat | `objectBoundingBox` units on a shape with no box | `gradientUnits="userSpaceOnUse"` |
| a label shows through a shape that should cover it | every `<text>` is drawn above every shape, whatever the document order | hide the label with `opacity="0"` while it should be covered |
| a line chart's segments (or a needle drawn as a `line` whose end moves) bend or sag during a glide | a path whose points change glides by the phone's own blend: a segment that changes direction bends on the way (the ends are exact) | scroll a series (the rest + slide recipe); draw levels with `rect`s or a dash; turn a needle with `rotate()` |
| ticks or a dotted line show as a solid stroke on the phone | the pattern is too fine or has too many dashes (the limits: `get_available_actions` topic `svg` → `widgetFaces.svgReference.recipes.dashes`) | fewer, larger dashes: a few dozen ticks per face, dash + gap ≥ 3 units (`svg-craft.md` → Ticks and dots) |
| where shapes of a half-transparent group overlap, the overlap is more opaque than in a browser | `opacity` on a `<g>` goes to each element (and to fill and stroke separately), not to the group as a whole | set the opacity on the shapes that should fade, or avoid overlaps inside a faded group |
| motion looks less fluid on an older iPad, in Low Power Mode or on a hot phone | such devices draw glides in fewer steps — by design | nothing to fix; keep glides at 0.3 s or longer |
| a page of widgets makes the phone warm or the motion stutters | too many cells glide at the same moment; or what moves all the time carries masks, gradient strokes, gradients on changing shapes, rounded gradient rects or clips that move or are not one upright rectangle; or its paths are larger than a cell or change their points | a `duration` shorter than the frame interval so cells rest; flat colors or square gradient rects on what moves all the time; paths cut to each cell and moved whole (`svg-craft.md` → Keeping the phone smooth) |
| text too small, or cut off | wrong scale for the button size; no margin | minimum sizes in `svg-craft.md`; 6–8 units of air; a bigger button |
| the widget is tiny in landscape | a rectangular button without a second layout | `landscapeSource` / `svgFaceLandscape`, or a square size |
| the button shows its icon, then the widget a moment later | no saved face | set `svgFace` to a neutral frame of the same template |
| a ⚠ count on the phone's toolbar; the button is in its list of errors | the startup script keeps failing or is restarting (the list shows its stderr), a frame was refused (the 400's reason), or the script reported an error through `/api/error` | fix the script or what it reported; exit code 0 means "finished, do not restart"; `get_startup_script_status` shows the same (`lastError`, `lastFrame`, `reportedErrors`) |
| the button's value stopped changing and nothing says why | the script survives its failure (no network, a refused key) and reports nothing | post the reason to `/api/error` on a change and `clear` once it works (`live-widgets.md` → Saying why it does not work) |
| `/api/error` answers `400` | an unknown field, a `cellId` that is not a UUID, a `kind` that is not one of the list, or no `kind` without `clear` | the body is `{"cellId", "kind", "message"}` or `{"cellId", "clear": true}`; the kinds: `errorReports` in `get_available_actions` topic `scripts` |
| two copies of one widget fight on a button (values flip, a scene shows two creatures) | a script of an agent that died (crash, Stop in Xcode) kept running | the agent kills such orphans when it starts and at every pairing, and their token stopped working when their agent died: reconnect the phone. Never `nohup` / `setsid` a widget loop |
| the Mac keeps asking to install the "command line developer tools" (a dialog about `python3`, `git` or `swift`), again about a minute after it was dismissed | a button's script runs `python3`, `swift` or `git` on a Mac without the Command Line Tools: `/usr/bin` has only stubs of them, and the agent restarts the failing script every minute | write the script in zsh (awk, curl, jq are on every Mac); if python is really needed, check `xcode-select -p` first and exit with the reason, as `assets/scene_template.zsh` does — `command -v python3` finds the stub and proves nothing |
| a script's posts get `401` | the script sends no valid token: a pasted one (it dies with the script it came from), a process the script left running after it ended (`&`, `nohup`, an app it opened), `$DESMAPTIC_TOKEN` empty or unset, or a process the agent did not start read `~/.desmaptic-mcp-token` before the token changed | read the token from `$DESMAPTIC_TOKEN` in a script the agent starts (the curl form in `live-widgets.md`); work that must outlive a tap belongs in the button's startup script; a program started elsewhere uses the socket, not the token |
| a script gets `403` from `/api/config`, `/api/deliver`, `/api/probe`, `/api/scripts` or `/api/restart-script` | those endpoints are for the MCP tools, not for button scripts | use the MCP tools (`get_profile_detail`, `get_startup_script_status`, `restart_startup_script`…) |
| a Mac notification answers `"mac":"denied"` | notifications are off for the agent — or the user has not answered macOS's request yet: on a new install the first notification to the Mac makes the agent ask, and that one is not shown | not answered yet: the user allows the request on screen, then send it again; turned off: System Settings → Notifications → Desmaptic Agent |
| a phone notification shows up late, only when Desmaptic is opened, or not at all (the answer had `"reason":"background"`) | Desmaptic was in the background: iOS suspends it about 30 s after it leaves the screen, and a suspended app receives nothing until it is opened; an app closed meanwhile (by iOS or swiped away) never gets it | send what must not be missed to the Mac too: `"targets":["phone","mac"]`, or post it again with `["mac"]` when the answer has `"reason":"background"` |
| `/api/notify` answers `403` "can only be sent by scripts the Desmaptic Agent started" | a notification with an action that runs something (shell, AppleScript, keys, typed text, a shortcut, a `file://` URL…) was posted by a process the agent did not start or that outlived its script (`nohup`, `setsid`, a background job, a terminal) | post it from the button's own startup, tap or long-press script, in its foreground |
| a notification action asks before it runs (Run on the Mac, a confirmation on the phone) | it was not sent by a button's script: a program on this Mac posted it through the agent's local socket (a hook, a terminal tool), or the agent that delivered it is too old to record who sent it | expected for anything but a button's own script; post it from the button's startup, tap or long-press script if it should run on the tap |
| `/api/notify` answers `400` "“origin” is set by the Desmaptic Agent" | the body carries an `origin` field | leave it out: the agent records who sent the notification from the connection |
| `/api/notify` answers `400` "action “…”: …" | an action's command holds a control or invisible character (the Unicode line separators included), is over 4,000 characters, or is a command type this agent does not know | plain printable text; call a helper script instead of inlining a long one; only the command types of `get_available_actions` |
| `get_startup_script_status` shows `notes` about the token | the startup script puts the token on a command line (`-H "Authorization: Bearer $DESMAPTIC_TOKEN"`, `${DESMAPTIC_TOKEN:-}`, or a variable filled from it or from `~/.desmaptic-mcp-token`) or carries a pasted token | switch to `curl -q` (`-q` first) with `--variable '%DESMAPTIC_TOKEN=' --expand-header 'Authorization: Bearer {{DESMAPTIC_TOKEN}}'`, or set the header in code |
| curl stops with a usage error at `--variable` (and a script that sends its output to `/dev/null` just never updates) | an older curl comes first in `PATH`: `--variable` and `--expand-header` need curl 8.3+ | call `/usr/bin/curl` (macOS 15 ships 8.7) |
| `get_startup_script_status` shows `held` | the script is not running yet: this agent's local API is not serving — another Desmaptic Agent of the account serves it, or port 9848 is held or cannot be opened (`held` says which) | nothing to resend: it starts by itself once the API serves; the agent window says the same |
| startup scripts do not start, and the agent window says another Desmaptic Agent serves, or port 9848 is busy | two agents in one macOS account (a Debug build next to the release one): only one serves widgets and AI tools; or another account's session holds the port | quit the other agent; a port held after a user switch frees itself within about 30 s |
| nothing updates at all | the phone is not connected, the wrong profile is active (startup scripts run for the active profile only), or the script died | `get_profiles`; `get_startup_script_status` (state + stderr of a dead script), `restart_startup_script`; Running Scripts in the agent window |
| works on this Mac, not on the other | the button calls a script file under `$DESMAPTIC_STORAGE` | put the whole script inline in `startupScript` |
| delivery "Not applied…" | the message names the cause: the user tapped Reject; **or the user accepted** but the place was taken / the page or button is gone; or no phone is connected | nothing changed. Only "tapped Reject" is a refusal — never tell the user they declined otherwise. "Place is taken": `get_page_layout` — the buttons may already be there from an earlier delivery; if not, pick a free cell and send again |
| the motion looks wrong on the phone (jerks, pauses, a part cuts across, a cross-fade) | frames the preview never saw: other steps, a frame that came early, a structure that changed | `view_live_button` with the button's id: the frames it really got, the glides between them and when each came. It draws each glide from the frame before, not from what the phone had on screen, so a seam that parts or a mover that leads does not show there (see the rows above); a move made in the hiding frame does show, as a fading copy sliding across in the in-betweens |
| delivery result says `status: pending` (UNKNOWN), or the AI client timed out the call | the user did not answer within the call (about 40 s) — the review is **still open** on the phone, and a later Accept applies the change | do not resend; once the user says they answered, call `get_delivery_status` with the `deliveryId` the result names (without one it reports the latest delivery), or ask the user |
| delivery "Not sent — … busy" | another change is still waiting on the phone: the phone holds one per Mac | ask the user to answer it, then `get_delivery_status` and send yours; if the waiting one is not yours, say so and ask the user to Reject it |
| the face cross-fades or jumps only on the user's phone, and the agent's answer carries a `compatibility` note about an empty `<text>` | a phone app older than 1.2.1 drops an empty `<text>`, so the structure changes | keep a character in the label and hide it with `opacity="0"` |
| no room for the widget | the page is full where you wanted it | `get_page_layout` lists the free positions per size; move or resize buttons with `update_buttons_by_uuid` (`row`/`col`/`rowSpan`/`colSpan` — buttons moved in one call can swap places). Deleting is the user's job, on the phone |
